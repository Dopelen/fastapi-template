# FastAPI template

Заготовка сервиса: FastAPI, PostgreSQL, Kafka. Показывает полный круг —
HTTP-запрос уходит в очередь, фоновый потребитель забирает его и пишет в базу,
результат читается обратно через API.

```
POST /send  ──>  Kafka  ──>  consumer  ──>  PostgreSQL  ──>  GET /events
```

---

## Запуск

Нужен только Docker.

```bash
docker compose up -d --build
```

Документация: http://127.0.0.1:8000/docs

Проверить круг целиком:

```bash
curl -X POST localhost:8000/send -H "Content-Type: application/json" -d '{"event_type":"demo","payload":"hello"}'
```

```bash
curl localhost:8000/events
```

Порядок запуска задан через healthcheck: приложение стартует только после того,
как Postgres и Kafka начнут принимать соединения. `depends_on` без условий
гарантирует лишь порядок контейнеров, но не готовность сервисов.

---

## Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/` | проверка живости |
| `POST` | `/send` | отправляет событие в Kafka |
| `GET` | `/events` | последние события из базы, `limit` и `offset` |

`POST /send` вернёт **503**, если брокер недоступен: это штатная ситуация,
а не сбой программы.

## Структура

```
app/
├── api/
│   ├── routers.py      эндпоинты
│   └── dependencies.py достаёт producer из app.state
├── config.py           настройки из окружения
├── db/postgres.py      движок, сессия, Base
├── kafka/
│   ├── producer.py     класс KafkaProducer
│   ├── consumer.py     класс KafkaConsumer: чтение и запись в базу
│   └── utils.py        ожидание брокера при старте
├── models/event.py     таблица events
└── schemas/event.py    схемы запросов и ответов
tests/                  на SQLite в памяти, инфраструктура не нужна
```

## Как это работает

**Клиенты Kafka хранятся в `app.state`**, а не в глобальных переменных модуля:

```python
app.state.kafka_producer = KafkaProducer()
await app.state.kafka_producer.start()
```

Поднимаются в `lifespan` при старте, останавливаются при выключении. Consumer
читает в фоновой задаче, которая живёт внутри самого объекта.

Роутер получает producer зависимостью `get_producer` — она достаёт его из
`app.state` и отдаёт **503**, если его там нет. Благодаря этому в тестах
подставляется заглушка одной строкой, без `monkeypatch` и `global`:

```python
application.state.kafka_producer = FakeProducer()
```

**Смещение подтверждается вручную, после записи в базу:**

```python
await save_to_db(msg.value)
await self._consumer.commit({TopicPartition(msg.topic, msg.partition): msg.offset + 1})
```

Это даёт доставку «хотя бы один раз»: падение между чтением и вставкой означает
повторную доставку, а не потерю. Обратная сторона — обработчик обязан быть
идемпотентным.

Битое сообщение всё равно подтверждается, иначе одна негодная запись
заблокировала бы топик навсегда. В настоящем проекте такие сообщения
отправляют в отдельный топик (dead letter queue).

**`group_id` обязателен.** Kafka хранит подтверждённые смещения по группе
потребителей. Без неё коммитить некуда, и при каждом старте топик читается
с самого начала.

**Схема создаётся при старте** через `Base.metadata.create_all`. Для шаблона
этого достаточно, но в настоящем проекте нужны миграции: `create_all` создаёт
только отсутствующие таблицы и не видит изменений в существующих.

## Разработка

```bash
poetry install
```

### Тесты

Инфраструктура не нужна: база подменяется на SQLite в памяти, приложение
собирается из роутера без `lifespan`, поэтому Kafka не поднимается.

```bash
poetry run pytest
```

### Запуск с машины

Скопируйте настройки и поднимите только инфраструктуру:

```bash
cp example.env .env
```

```bash
docker compose up -d postgres kafka
```

```bash
poetry run python -m app.main
```

В `.env` хосты указаны для запуска снаружи Docker: `localhost` и порт `29092`
для Kafka. Внутри сети используются имена сервисов — `postgres` и `kafka:9092`,
они задаются в `docker-compose.yml` напрямую.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_NAME` | `FastAPI Template` | заголовок приложения |
| `APP_HOST` / `APP_PORT` | `0.0.0.0` / `8000` | для запуска через `python -m app.main` |
| `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASSWORD` | см. `example.env` | из них собирается строка подключения |
| `KAFKA_BROKER` | — | адрес брокера |
| `KAFKA_TOPIC` | — | топик |
| `KAFKA_GROUP` | `default-group` | группа потребителей |
| `SQL_ECHO` | `false` | печатать SQL в консоль |

Строка подключения к базе собирается из частей в `app/config.py` и отдельной
переменной не задаётся — иначе части и готовый DSN неизбежно разъезжаются.

---

## Чего здесь нет

Это заготовка, а не готовый сервис. Сознательно не сделано:

- **миграции** — схема создаётся через `create_all`, для развития нужен Alembic;
- **dead letter queue** — необработанные сообщения просто пропускаются с записью в лог;
- **аутентификация** — эндпоинты открыты;
- **TLS** — ни у HTTP, ни у Kafka.
